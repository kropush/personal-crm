# Личная CRM

Приложение для контактов людей, которых знаешь лично: кто это, откуда знакомы, телефон и почта, заметки после разговоров.

Что умеет:

- показывает список всех контактов;
- ищет контакт по имени;
- добавляет новый контакт;
- меняет данные контакта: имя, кто это, откуда знакомы, телефон и почту;
- в карточке контакта хранит заметки — о чём поговорили и о чём договорились.

Идея и границы продукта описаны в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что должно быть установлено

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных;
- [Node.js](https://nodejs.org/) версии 20.12 или новее;
- [pnpm](https://pnpm.io/installation).

## Первый запуск

Все команды выполняются в терминале, в папке проекта.

1. Создайте файл `.env` рядом с `.env.example`: скопируйте `.env.example` и впишите значения. Пароль придумайте сами — он нужен только для локальной базы.
2. Запустите базу данных:

   ```
   docker compose up -d
   ```

3. Установите зависимости:

   ```
   pnpm install
   ```

4. Создайте таблицы в базе:

   ```
   pnpm db:migrate
   ```

5. По желанию наполните базу тестовыми данными — 1000 выдуманных контактов с заметками:

   ```
   pnpm db:seed
   ```

6. Соберите и запустите приложение:

   ```
   pnpm build
   pnpm start
   ```

7. Откройте в браузере <http://localhost:3000>.

## Обычный запуск

Когда всё уже настроено, достаточно двух команд:

```
docker compose up -d
pnpm start
```

Приложение работает, пока открыт терминал с `pnpm start`. Остановить его — `Ctrl + C`. Остановить базу — `docker compose stop`.

## Как проверить, что всё работает

1. Откройте <http://localhost:3000> — виден список контактов.
2. Нажмите «Добавить контакт», впишите имя и сохраните — список откроется на новом контакте, он подсвечен.
3. Впишите имя в поле «Найти по имени», откройте карточку, напишите заметку и нажмите «Сохранить заметку» — заметка появится в карточке.
4. В карточке нажмите «Изменить», поправьте, например, телефон и нажмите «Сохранить изменения» — карточка откроется с новыми данными.
5. Откройте тот же адрес в другом браузере — там те же контакты, та же заметка и те же изменения.

## Команды

| Команда | Что делает |
| --- | --- |
| `docker compose up -d` | запускает базу данных |
| `docker compose stop` | останавливает базу данных, данные остаются |
| `pnpm build` | собирает приложение; нужно повторять после изменений в коде |
| `pnpm start` | запускает собранное приложение |
| `pnpm dev` | запускает приложение в режиме разработки: изменения в коде видны сразу, но работает медленнее |
| `pnpm db:migrate` | создаёт и обновляет таблицы в базе |
| `pnpm db:generate` | создаёт файл миграции после изменения схемы в `src/db/schema.ts` |
| `pnpm db:seed` | наполняет пустую базу тестовыми данными |
| `pnpm lint` | проверяет код |

## Где лежат данные

Контакты и заметки хранятся в базе PostgreSQL, которая работает в Docker. Данные лежат в томе Docker и переживают перезапуск компьютера и контейнера.

Осторожно с двумя командами — они удаляют данные без возможности вернуть:

- `docker compose down -v` — удаляет базу целиком;
- `pnpm db:seed --reset` — удаляет все контакты и заметки и заново создаёт тестовые.

Обычная `pnpm db:seed` ничего не удаляет: если в базе уже есть контакты, она остановится и ничего не изменит.

## Выкатка на сервер

Приложение работает на <https://app.kropcrm.ru>. Новая версия выкатывается сама, когда изменения попадают в ветку `main` на GitHub.

### Как выкатить новую версию

1. Отправьте изменения в `main`: `git push` или слияние PR на GitHub.
2. На GitHub откройте вкладку **Actions** — там идёт выкатка «Deploy». Она занимает несколько минут.
3. Зелёная галочка — новая версия на сервере. Красный крестик — выкатка не удалась; GitHub пришлёт письмо.

Что происходит по шагам:

1. GitHub собирает образ приложения и кладёт его в GHCR (хранилище образов GitHub). Имя образа — SHA коммита, например `ghcr.io/kropush/personal-crm:3dcdde3…`.
2. GitHub заходит на сервер по ключу деплоя, копирует туда папку `deploy` и запускает `deploy/deploy.sh`.
3. На сервере скрипт скачивает образ и сначала применяет миграции базы — разовым контейнером из того же образа. Если миграции упали, новая версия не запускается, старая продолжает работать.
4. Запускается новая версия приложения. Пока она стартует, сайт несколько секунд недоступен.
5. Проверка: `/health` должен ответить `200` — и напрямую, и через nginx. Не ответил — выкатка красная.
6. На сервере остаются только образы текущей и предыдущей версий, старые удаляются.

### Как проверить

- Откройте <https://app.kropcrm.ru> — виден список контактов.
- Откройте <https://app.kropcrm.ru/health> — видно `{"status":"ok"}`.
- В **Actions** на GitHub последняя выкатка — с зелёной галочкой.

### Если выкатка упала

Скрипт ничего не откатывает сам. Что сломалось — видно в **Actions**: откройте красную выкатку, шаг «Deploy to the server».

- Сбой случайный (например, не скачался образ) — нажмите в выкатке **Re-run jobs**.
- Нужно вернуть предыдущую версию — откат вручную:

  ```
  ssh crm
  cat /srv/personal-crm/release-previous
  /srv/personal-crm/deploy/deploy.sh <SHA из предыдущей строки>
  ```

  Откат возвращает код, но не таблицы: если новая версия меняла таблицы базы, старой версии они достанутся уже изменёнными.

### Что лежит на сервере

- `/srv/personal-crm/.env` — пароль и имя базы. Создаётся один раз руками, читает только владелец. В git его нет, выкатка его не трогает.
- `/srv/personal-crm/deploy` — копия папки `deploy` из репозитория, обновляется при каждой выкатке.
- `/srv/personal-crm/release-current` и `release-previous` — SHA текущей и предыдущей удачных версий.
- База данных — в томе Docker `prod_postgres-data`. Выкатка её не удаляет.
- Настройки nginx для `app.kropcrm.ru` — `/etc/nginx/sites-available/app.kropcrm.ru.conf`, копия — `deploy/nginx/app.kropcrm.ru.conf`. Выкатка их не меняет; если поменяли файл в репозитории — команды для установки написаны в его начале.

Посмотреть, что запущено, и логи приложения:

```
ssh crm
docker ps
docker logs --tail 100 prod-app-1
```

## Как устроен проект

- `src/app` — страницы: список контактов, новый контакт, карточка контакта, изменение контакта; `/health` — проверка после выкатки;
- `src/components` — части интерфейса;
- `src/lib` — работа с контактами, проверка введённых данных;
- `src/db` — схема таблиц, подключение к базе, миграции, тестовые данные;
- `drizzle` — миграции базы данных;
- `compose.yaml` — настройки базы данных в Docker для запуска на своём компьютере;
- `Dockerfile` — как собирается образ приложения;
- `.github/workflows/deploy.yml` — автовыкатка на GitHub;
- `deploy` — скрипты выкатки и настройки сервера.

Стек: Next.js (App Router), TypeScript, React, Tailwind CSS, shadcn/ui, PostgreSQL, Drizzle, pnpm.
